## 1. Headline answer to "7 skills — is that too many?"

**No. The count is right; the weight is wrong.**

The seven map cleanly onto lifecycle verbs (start / discover / generate / run /
analyze / optimize / help) with no two overlapping in *purpose*. Keep all seven.

The problem is size and density (CONFIRMED by measurement):

| Metric | Value |
|---|---|
| Total skill prose | **~33,900 tokens** |
| `run` + its refs + case-format + adapter-contract | **~12,800 tokens loaded before one case executes** |
| `generate` + its refs | ~9,400 tokens |
| Avg sentence length across skills | **22–29 words** (README 34) |

22–29 words/sentence is academic-paper density. Instruction prose that an LLM
must *follow procedurally* should be ~12–18. The rationale is genuinely good
writing — it just belongs in `references/`, not in the instruction body.

**Only real merge candidate:** `help` (~1,400 tok) mostly restates README +
`concepts.md`. Either make it a thin pointer, or fold it into `start`, which
already ends every turn with "where you are / what's next."

Three things this changes:

   `SKILL.md` comes back as a reference.** That *is* rec 5 ("move rationale to

2. **The −62% on the headline number is not a writing win.** Step 5c deleted

3. **Lines were the wrong proxy, confirmed twice.** The four slimmed skills sit

`reports/baseline.json` 7 (was 8 — Step 6 removed one). `skills/help/SKILL.md`
is in **all three lists**, which resolves this section's "only real merge
candidate" note: every one of its seven sections is owned elsewhere — by
`README`, `docs/workflow.md`, `docs/concepts.md` and `optimize` §Preconditions,

## 2. THE architectural finding: there is no execution engine

CONFIRMED: nothing in `scripts/` opens a socket, spawns a process, reads
`adapter.yaml`, or parses YAML at all. Grep for
`urllib|requests|http.client|subprocess|socket|yaml` across `scripts/` returns
only comments. Every script is a pure function: JSON in → JSON out.

So `run/SKILL.md` §2 "Execute" — resolve the adapter, invoke the app, k
repeats, bounded retries, collect + join traces, write the per-case tree
atomically via temp-then-rename, support resume, build the JSONL rows each
scorer needs, assemble `verdicts.jsonl` / `verdicts_for_stats.jsonl` /
`results.json` — is **done by the LLM, by hand, every single run**.

Consequences:

1. **Not reproducible.** The manifest pins dataset version, app SHA, model,
   judge, rubric, harness version — but not the orchestration. Two runs of the
   same suite are two different programs. This quietly undercuts the plugin's
   own "comparability or nothing" principle.
2. **Cost is dominated by orchestration**, not by the app under test.
3. **The mandatory contract silently drifts.** CONFIRMED, empirically:
   `field-test-qa/.agent-eval/reports/smoke-20260818T183920Z/` — the most
   recent run, produced by following `run/SKILL.md` — is **missing
   `verdicts.jsonl` and `verdicts_for_stats.jsonl`**, both of which the skill
   declares required. `verdicts_for_stats.jsonl` is the *only* input
   `stats.py` pairs, so the baseline diff — the plugin's central claim —
   cannot run against its own worked example.
4. It contradicts the skill's own opening line: *"you do not eyeball-score
   anything a script can score."* The identical argument applies to execution.

**Recommendation — the single highest-leverage change: add `run_cases.py`.**
One stdlib-only runner that takes the adapter config + case list **as JSON**
(same "caller converts YAML" trick `validate_cases.py` already justifies at
length in its docstring, so the stdlib-only rule survives intact), executes,
retries, writes the per-case tree atomically, emits the three required
machine-readable files, and shells out to the existing scorers.

Knock-on effect: `run/SKILL.md` collapses from 305 lines of hand-orchestration
to ~60 lines of "call the runner, read the report, cluster the failures." That
one change fixes reproducibility, cost, contract drift **and** skill bloat at
once.

## 3. CONFIRMED broken contract between skills: splits, field vs directory

`generate/SKILL.md:347` states splits are **a field on the case**
(`split: [full, smoke]`), *"not a directory copy"* — with a good argument for
why (two files, one id, no source of truth).

But `run/SKILL.md`, `run/references/run-modes.md`, and `optimize/SKILL.md`
still select cases **by directory path**: `datasets/smoke/`,
`datasets/holdout/`, `datasets/full/`, `datasets/canary/` (9 references across
3 files).

So `generate` now produces field-tagged cases and `run` looks for directories
that generate no longer creates. Mode selection is broken, and the **holdout
seal** — the thing the optimizer's whole keep/revert gate rests on — depends
on this same mechanism.

This is the duplication tax caught in the act. See §4.

## 6. CONFIRMED bug I found myself: `--oos-route` is unvalidated

```
$ score_routing.py routing_results.jsonl --oos-route TOTAL_NONSENSE_XYZ
exit 0
oos = {"precision": null, "recall": null, "support": 0,
       "note": "not measurable: ... 0 OOS case(s) in this run."}
```

The data contains **2** OOS cases. The correct label is `none`; with it, the
metric computes fine (P=1.0, R=1.0, support=2). The `--oos-route` value is
LLM-supplied from `profile.yaml`'s `oos_handling`, so any mismatch or typo
**silently disables the out-of-scope leakage metric** — a security-adjacent
number — and emits a note that is factually false about the run.

Fix: if `--oos-route` matches no label present in the input, exit 2 with
`"--oos-route 'X' matches no label in the data (labels present: ...)"`.

(Note: I initially suspected the shipped `routing_report.json` was
inconsistent with its own JSONL. It is not — `__oos__` is the scorer's
canonical internal label and the report reproduces exactly with
`--oos-route none`. Not a finding.)

## 7. The validator's most important checks are opt-in or absent

Ran `validate_cases.py` on the shipped 12-case field-test dataset: exit 0,
7 warnings (6× `machine_accepted`, 1× `single_turn_suite`). What it did **not**
catch, CONFIRMED from the output and the code:

- `by_split: {}` and `by_test_type: {}` — **empty, with zero findings**. Split
  and `test_type` are only validated *if present* (`validate_cases.py:448`,
  `:474`). Absent = silent pass. So: no mechanical enforcement of holdout
  membership (the seal has no backing), and no INV/DIR coverage floor despite
  generate calling INV "the cheapest coverage in the grid."
- `template_id` / `instantiation_params` are declared **"required, not
  optional"** in generate §2a — but the check only fires when *one of the two*
  is present. All 12 cases have neither → nothing fires.
- `--capabilities` is **optional**, and without it every layer counts as
  enabled. That means the check generate itself calls *"the most expensive
  failure mode in this whole skill"* (cases asserting layers the profile has
  disabled) **defaults to off**. It should be required, or absent-should-warn.
- `analyze` performs exactly the case edits generate §4 says require
  re-validation — but `analyze/SKILL.md` never mentions `validate_cases.py`.
  The instruction lives in the skill that won't be loaded when the edit happens.

## 9. Scorer audit — DONE (the subagent died on a rate limit; I did it directly)

### 9a. What is CLEAN (verified by running it, not by reading)

The scoring code is **high quality — better than typical for this kind of
harness.** Do not touch these:

- **The statistics are correct.** I re-derived each formula independently:
  the Beta closed form `P(Beta(1+b01,1+b10) > ½) = Σ_{k<a} C(n,k)/2ⁿ` is right
  (spot-checked: b01=3,b10=0 → 0.9375 = 1−2⁻⁴ ✓); the exact one-sided binomial
  tail is right; `mcnemar_exact_p_two_sided` correctly uses the symmetry
  `P(X≤lo) = P(X≥n−lo)` to reuse one exact-tail implementation; the MDE
  inversion in the `advice` block is algebraically consistent with
  `min_detectable_effect`. The sidedness reasoning in the docstrings is
  unusually careful and correct.
- **HTML escaping is properly hardened, both paths.** Fed
  `</script><script>`, `</SCRIPT >`, `<svg/onload=>`, `javascript:` hrefs and
  raw U+2028/U+2029 through `md_to_html.py` and `build_review_viewer.py`: no
  breakout. The JSON blob escapes `</script>` → `</script>` and
  U+2028/29 → ` `/` ` (the subtle one). `safe_href` drops
  `javascript:` links entirely. Commit `8f79b52` did this work; it holds.
- **`trajectory_match.py` uses MULTISET, not set, semantics.** Asserting
  `subset: [search, search, get]` against one `search` correctly yields
  recall 0.667 and `missing: ["search"]`. Non-obvious and right.
- **`score_answer.py` regex handling is genuinely good.** A catastrophic-
  backtracking pattern `/(a+)+$/` is caught by a **2-second watchdog** →
  `unscorable` with a clear reason, not a hang and not a manufactured fail.
  An invalid regex → `unscorable`, not a silent fail.
- **`score_execution.py`'s RecursionError is fixed.** 1,500 rows reversed,
  and 1,200 rows forced down the *fuzzy* float-tolerance path (values off by
  1e-9, so exact bag hashing can't short-circuit): both exit 0, no recursion
  blowup. `REVIEW-2026-08-08.md` §2.5 item resolved.
- **`score_authz.py`'s HIGH bug is fixed.** Empty `--answer` now yields
  `unscored` / `unscorable`, not `pass`. `--id-pattern` works: a UUID is
  `unscorable` without it, `pass` with it — honest degradation, no false pass.
- **Python 3.9 floor is clean.** No `match`, no runtime PEP-604 unions (the
  two `X | Y` grep hits are prose in docstrings), no 3.10+ stdlib APIs.
- **Every `--flag` referenced in a skill/doc exists on the script it is
  invoked against** (checked per-script, not just globally).
- `python3 -m unittest discover -s tests` → **399 tests, OK** (32s); ruff clean.
- All 14 scripts respond to `--help` rc=0 (the July QA crash is fixed).
- No orphan scripts (`_common.py` is a library, correctly so).

### 9b. NEW confirmed defects

**(1) `stats.py` — sub-MDE keep is reported with no warning at all. MEDIUM-HIGH.**
This is the optimizer's decision point. Repro:

```
baseline 90/100 pass, candidate 95/100 (b01=5, b10=0)
→ delta 0.05, min_detectable_effect_at_this_n 0.056
→ keep: true,  gate_note: ABSENT,  advice: ABSENT
```

The gate kept a change whose observed effect is **below its own stated
detectable threshold**, and said nothing. The two existing guards both miss it:
`gate_note` fires on "sign test not significant" (here it *was* significant,
p=0.031), and `advice` is gated behind `not keep`. The file's own MDE text
anticipates exactly this — *"treat a sub-MDE 'keep' as not proven"* — but
nothing tells the caller this run is one. `optimize` §5 then pins it as the new
baseline and reports a bare "kept".
**Fix:** emit `sub_mde_keep` whenever `keep and abs(delta) < mde`, and have
`optimize` surface it the way it already surfaces `gate_note`.

**(2) `score_answer.py` — no Unicode normalization. MEDIUM.**
A `must_contain` of `café` authored in **NFD** fails against an **NFC** answer
that a human reads as identical (verified: `status: fail`). This is a
manufactured failure — the exact class the plugin's own docstrings forbid.
It bites harder here than usual: `generate` §2c lists **language** as a
generation dimension, cases are LLM-authored and human-reviewed in a terminal
where NFC/NFD is invisible, and macOS filesystems/editors emit NFD. The
field-test app is Gulf-market (Arabic normalization variance — alef forms,
tatweel, presentation forms — is far worse than the accent case).
**Fix:** `unicodedata.normalize("NFC", ...)` on both sides for plain-string
entries; normalize the haystack for regex entries and say so in the output.

**(3) `score_routing.py` — `--oos-route` is unvalidated.** See §6 above.

**(4) `partially_unscored` is produced but never required to be shown. LOW.**
`score_answer.py` correctly emits `verdict: pass` + `partially_unscored: true`
+ `unscorable: 1`. But the flag appears in **`case-format.md` only** — not in
`run/SKILL.md`'s report requirements and not in `results.json`'s specified
shape. So a case whose check silently didn't run can be quoted in the report
as a clean pass. The honest signal exists; nothing obliges anyone to read it.

**(5) Informational — the `delta > 0` conjunct in the keep rule.**
`REVIEW-2026-08-08.md` called it dead. It is redundant for any
`--bayes-threshold ≥ 0.5` (since `delta > 0 ⟺ b01 > b10 ⟺ prob > 0.5`), but it
*does* bite if someone passes a threshold below 0.5, which `require_range`
currently permits. Either keep it and say why, or reject a threshold ≤ 0.5 with
a clear message.

## 13. The reshape, in one line

This is two good products fused by a weak seam: an **eval methodology** worth
publishing as a document, and a **scoring harness** of 14 solid pure functions
— glued together by LLM hand-orchestration. Make the harness a real CLI, make
the skills thin, publish the methodology as docs. The skills stop being essays
and become what they should be: the part that decides *what to do next*.
