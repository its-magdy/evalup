## 1. Overall verdict

**The plugin is genuinely good — validated against the state of the art, not
just self-belief.** Its design already embodies what the best 2025–26 tools
converged on:

| Plugin design choice | External validation |
|---|---|
| Trace-grounded reflective optimization, sealed holdout, budget, one-candidate loop | GEPA (arXiv:2507.19457) — the current best-in-class optimizer discipline |
| Deterministic-first scoring; judge only for what scripts can't check | Ahead of most commercial tools (which over-use LLM judges) |
| Subset trajectory matching by default, order only when human-stated | Exactly what LangSmith AgentEvals ships (`subset`/`unordered` modes) |
| Judge calibration as TPR/TNR/κ vs human labels, PROVISIONAL watermark | LangSmith "Align Evals" pattern, but stricter |
| Decomposed-binary reference-guided rubric DAG | Agent-as-a-Judge research (~88–90% human alignment vs ~60–65% holistic) |
| Failure → dataset promotion (`analyze --mine`) | Universal best-practice ("regression from failure") |
| Run-mode taxonomy (smoke/regression/targeted/holdout/full), pass^k, canaries | Matches/exceeds promptfoo & Braintrust practice |
| OTel GenAI-span normalization as the framework-agnostic seam | Same bet as Phoenix/promptfoo |

Nothing in the research says "throw this away and copy X." Everything below
is defects and gaps, not direction changes.

## 2. Confirmed bugs (fix first — all reproduced, none covered by tests)

1. **`score_authz.py` — HIGH.** An **empty `--answer` file converts
   "unscorable" into a confident "pass"** on the security gate.
   `answer_text = ""` is not `None`, so `[""]` becomes a non-empty haystack
   list; the no-evidence guard misses; forbidden-record checks pass with zero
   evidence (content capture off, app refused with empty body). Fix: filter
   empty/whitespace haystacks. This is the manufactured-verdict class the
   plugin's own docstrings forbid, on the worst possible layer.
2. **`score_routing.py` — HIGH.** Macro-F1 averages in **zero-support
   prediction-only labels** (`__no_route__`, hallucinated route names) as
   hard 0.0s. Repro: one unrouted case out of 4 dropped macro-F1 from 0.83 →
   0.56, and the >0.1 macro/micro-gap warning then misdiagnosed it as
   "minority targets underperforming." Makes the headline routing number
   non-comparable across runs. Fix: average over labels with support > 0;
   report spurious prediction labels separately.
3. **`stats.py` — HIGH (design).** **Silent case attrition**: baseline ∩
   candidate with no warning. Infra verdicts are filtered upstream, so the
   cases a candidate *crashed on* silently vanish from the keep/revert
   comparison — invisible selection bias at the decision point. Fix: report
   `cases_only_in_baseline/candidate`; refuse or loudly warn above a
   threshold.
4. **`score_args.py` — MEDIUM.** Arg assertions apply to **every call** of
   the named tool; no `any_call`/`first_call`/index selector. An agent
   calling `search` twice with different args (paginate/refine/retry)
   manufactures a failure. The single most likely false-failure source in
   the whole scoring model. Fix: add a call-scope selector (default
   `any_call`), plus an escape form so the literal strings
   `"present"`/`"from_tool_result"` are assertable.
5. **Smaller confirmed items:**
   - `score_authz.py`: `RECORD_ID_RE` only matches `letters[-_]digits` —
     integer PKs, UUIDs, ULIDs invisible → leak-check silently unscorable on
     most real schemas. Add `--id-pattern`. Also: `allowed_record_ids` scans
     results only (asymmetric with forbidden); `forbidden_tools` can't
     distinguish a fired call from a 403-rejected one.
   - `score_execution.py`: `bag_match` recurses — `RecursionError` (exit 1 +
     traceback, outside the exit-2 contract) at ~1000 rows; O(n²) adjacency
     build. Cap n cleanly or make the matching iterative. Also: bare-number
     unit rule (`5 == "5 kg"`) is very permissive — consider `strict_units`.
   - `detect_loops.py`: emits `pass`/`fail` in the correctness vocabulary —
     a call-budget overrun on a legitimately long task reads as a
     correctness regression in stats. Should emit findings + severity, not a
     verdict. Repeats also counted globally (polling/pagination
     indistinguishable from loops).
   - `stats.py`: docstring claim "no normal approximation anywhere" is false
     for the MDE / "cases you need" numbers (NormalDist via `z_sum`); the
     `delta > 0` conjunct in the keep rule is dead; no multiplicity control
     for repeated gate runs.
   - `normalize_trace.py`: `tool_calls_without_result` silently skips calls
     with no `call_id` → a trace with no ids reports "everything captured."
   - `score_answer.py`: `verdict: pass` can sit on top of `unscorable > 0`
     checks (consumers keying on verdict see a clean pass); JSON-schema
     `enum` lets `True` satisfy `[1]`.
   - `trajectory_match.py`: precision penalizes extras in `subset` mode
     where extras are explicitly allowed — misleading on dashboards.
   - `reduce_repeats.py`: `k` defaults to the minimum repeat count across
     cases — one under-sampled case silently changes the metric for all;
     surface it in output.
   - `build_review_viewer.py`: page size unbounded (full raw records
     embedded + all detail HTML rendered up front); `build_page` mutates
     input records.

**Test-suite note:** coverage is strong and behavioral (subprocess-level,
exit codes, even node-booted JS for the viewer) — but every bug above is
untested, there is no coverage measurement, no CI, and no property tests for
the statistics (`pass^k ≤ pass@k`, posterior monotonicity, two-sided ≥
one-sided would pin definitions by invariant).

## 4. Structural gaps — the docs promise more than the scripts can do

The scoring pipeline is structurally **single-turn, single-agent,
single-trace**, while discover/adapter/docs promise multi-agent and
multi-turn. Biggest honesty gap in the plugin today.

1. **Multi-turn**: adapter has a `session` contract, case format has message
   arrays — but `normalize_trace.py` takes one `--trace-id`, no session
   envelope, no turn index, no "by turn 3…" expectation grammar. The
   `simulated-user` agent generates conversations nothing can fully score.
2. **Multi-agent**: discover promises "per-handoff capture" for
   `multi_agent`, but normalized tool calls carry no agent attribution, no
   span/parent ids, no handoff edges. Cannot express "the billing subagent
   must not call `delete_user`"; `detect_loops` mis-flags two subagents
   making the same call; none of the research's multi-agent metrics
   (per-agent ablation/marginal utility, consensus rounds, vote entropy)
   exist. **Highest-leverage single change: add `span_id`/`parent`/owning
   agent to every tool call + a session envelope above the trace** — it
   unblocks authz scoping, per-agent loops, cost attribution, and multi-turn
   at once (the normalizer already walks the parent chain for token rollup;
   it discards structure it computed).
3. **Cost/latency are decorative**: the viewer renders a `cost_usd` column
   nothing computes; no price table, no cached-token accounting, no TTFT, no
   percentiles. `stats.py` compares only binary verdicts — "2% better but 3×
   more expensive" is indistinguishable from a free win. Add continuous
   paired comparison (bootstrap) beside the binary gate.
4. **Judge loop not closed in code**: calibration/agreement (TPR/TNR/κ) is
   described everywhere but no script computes it; the viewer exports
   annotation JSONL that nothing reads back. Belongs in a deterministic
   `score_agreement.py`.
5. **No per-layer statistics**: layering exists for credit assignment, but
   `stats.py` takes one verdict per case; no per-layer gate, no
   multiplicity correction across layers.
6. **No RAG/retrieval layer**: context precision/recall, groundedness,
   chunk attribution absent — and retrieval-augmented chat is arguably the
   most common "AI feature in an app." Even a deterministic "answer cites
   only retrieved chunks" check would cover a lot.
7. **Environment lifecycle**: seed/reset/snapshot are contracted in
   adapter.yaml but no script drives state-diff scoring — write-action
   correctness (what agents most get wrong) is out of reach.
8. **Streaming**: adapter declares `streaming`/TTFT; nothing measures it.
9. **No run history / longitudinal view.** Runs are durably persisted
   (manifest, per-case verdicts, reports, flakiness ledger) — good — but
   comparison is only ever *pairwise vs one baseline*. There is no
   trend-over-runs view, so five consecutive −2% "within noise" diffs hide a
   10-point erosion; no per-case journal ("case X: passed runs 1–7, failed
   after prompt change Y, fixed in 11"); no run index listing all runs with
   headline numbers. All the data is already on disk — this is a cheap
   aggregation layer: a stdlib `run_history.py` emitting per-metric time
   series (flagging monotone drifts) + a per-case history tab in the review
   viewer.
10. **Schema fields with no scorer behind them.** The case format promises
   measurements nothing computes: `template_id`/`instantiation_params`
   ("variant consistency scored later" — no scorer), `difficulty`
   ("stratified reporting, never blended" — no script stratifies; depends on
   the LLM remembering), `excluded_tools` (relevance test — nothing scores
   it; trajectory_match only knows `forbidden`, a different semantic). Build
   the small scorers (~50 lines each on existing plumbing) or mark the
   fields reserved.

## 5. Ideas worth stealing from the research

- **PromptWizard — failure→example synthesis**: when optimize identifies a
  failure cluster, also *generate new eval cases* targeting that weakness —
  the suite grows as a side effect of optimization. All pieces exist
  (test-generator, clusters); it's a paragraph in optimize/SKILL.md.
- **GEPA — Pareto frontier, taken seriously**: the candidate-pool paragraph
  gestures at it, but per-case score vectors and "merge complementary
  candidates" have no mechanics. Matters most for multi-agent apps where one
  edit helps one sub-agent and regresses another.
- **AgentEvals — reference-free judge-rubric trajectory mode**: rubric-judged
  "were the agent's decisions reasonable" for apps with no golden paths —
  gated behind calibration like everything else.
- **Judge bias mechanics** (arXiv:2602.02219 etc.): rubric-option order bias
  exists even in pointwise judging — worth a line in the judge agent
  (randomize option order in calibration batches).
- **Property tests for the statistics** (see §2 test note).
- (Also researched: langchain-skills' `eval-engineering` skill — precedent
  confirming the "inspect agent → propose eval plan" packaging is the right
  UX shape, which `start`/`discover` already do.)

## 6. What to remove or slim

- **`.NET-first adapter depth**: `adapters/dotnet.md` is the only reference
  adapter; a Python/TypeScript one would serve the "general-purpose" claim
  far better (that's where most LLM apps live). Keep dotnet, add
  python/typescript, de-emphasize .NET specifics in discover.
- **`micro_f1` in routing output**: algebraically identical to matrix
  accuracy; invites over-reading. Report once or drop.
- **Python 3.9 floor essay in README**: keep the floor, cut the three-depth
  ceremony to two lines + a CI job.
- **Skill-file repetition**: run/discover are very long and restate each
  other's rules (comparability, `safe_to_attack` appear 3+ times). Skills
  load into context per invocation — dedupe to one owning doc; the
  repetition costs real tokens every run.

## 8. Why the plugin contains Python code (and should keep it)

The scripts layer is the plugin's best design decision, not an accident:
deterministic scoring is what makes numbers **reproducible** (an
LLM-eyeballed score is noise on top of the statistics), **free** (hundreds of
case×layer×repeat scorings per run cost zero tokens), **CI-gateable** (the
"LLM never in the gate path" rule requires a script-produced verdict a
tokenless shell step can read), and **comparable** ("same harness version =
same metric meaning" only holds for versioned code). The legitimate critique
is "why hand-rolled instead of DeepEval/sklearn" — answered by the
stdlib-only portability goal, which is right for a plugin, but it is exactly
why the harness needs its own golden-trace verification suite in CI (the
macro-F1 and authz bugs are the price of reimplementation).

## 9. Metrics audit

The inventory (routing accuracy/P/R/F1/confusion/OOS; trajectory
subset/order/forbidden + P/R; args; loops; answer checks; execution QEM/bag;
authz; pass@k/pass^k/flakiness/crash; latency/tokens; Bayesian gate + sign
test; judge TPR/TNR/κ) is well-chosen — every metric serves credit
assignment ("which prompt do I fix"), none is vanity. Issues:

- **Redundant**: `micro_f1` ≡ matrix accuracy (drop/label); loop detection's
  pass/fail is an efficiency signal wearing a correctness verdict (§2).
- **Promised but not computed**: see §4 item 10 (template consistency,
  difficulty stratification, excluded-tools relevance) and §4 item 3 (cost).
- **Questionable**: `GEvalNode`'s graded score ranges are the one non-binary
  element in a deliberately binary-or-unscorable system — graded scores
  can't be calibrated as TPR/TNR. Consider removing GEvalNode or demoting it
  to diagnostic-only, never in any aggregate.

## 10. Claim verification (web-checked 2026-08-08)

Key citations in the plugin's docs were verified against
papers/official docs. Confirmed: MT-Bench reference-guided ~70%→~15% judge
failure on math; τ-bench pass^k + DB-state ground truth; DeepEval
PlanAdherence auto-passes (score 1) when no plan found; DeepEval
Hallucination=curated context vs Faithfulness=retrieval context;
`--permission-mode dontAsk` and `--output-format json` officially
documented; `${CLAUDE_PLUGIN_ROOT}` + plugin structure correct; OTel GenAI
`invoke_agent`/`execute_tool`/`gen_ai.agent.name`/`gen_ai.tool.name` real
(semconv still "Development" stability — pin a semconv version in the
normalizer); exact one-sided sign test = exact McNemar on discordant pairs;
Beta posterior P(improvement) standard.

**Corrections needed in the plugin's docs:**
- **GEPA numbers**: it's ~10% (up to +12%) over MIPROv2, and up to 35×
  fewer rollouts **vs GRPO** (loop-discipline.md attributes correctly;
  double-check other mentions).
- **Agent-as-a-Judge**: actual figures 90–92% vs 60–84% for LLM-as-a-Judge
  depending on setting — the "~60–65%" phrasing in judge.md/rubric-format.md
  undersells the baseline's range; soften.
- **AppWorld "SGC"** = *Scenario Goal Completion*, not "template
  consistency" as case-format.md implies; and AppWorld's no_op sanity check
  could not be verified — re-derive or drop the attribution.
- **`--bare` flag**: real but currently undocumented in the official CLI
  reference (open issue #36852); the `system/init` `plugin_errors` check is
  not an official documented pattern — plugin load failures currently
  surface as generic hook errors (#33606). run-modes.md should note both as
  best-effort, not contract.
- **"~74% of business policies deterministically checkable" is
  unsupported** — no source found; the only ~74% nearby is a GPT-4.1
  τ-bench pass rate (unrelated). Remove the number from concepts.md and
  rubric-format.md or re-derive it; keep the qualitative claim ("most").

**Second verification pass (remaining citations + best practices):**

Confirmed: arXiv:2607.14004 (GEPA gains fail to transfer without regression
control), arXiv:2605.29800 (single judge ≥ panel — 9 judges ≈ 2 effective
votes), arXiv:2604.15579 (symbolic guardrails), EvalGen 2404.12272
("criteria drift" verbatim), GAIA quasi-exact match (exactly what
score_execution implements), metamorphic testing as established practice,
SKILL.md format + `references/` progressive disclosure (<~500-line body
guidance), agent frontmatter `model:`/`tools:`, plugin.json (only `name`

**Further corrections needed:**
- **Tool-description "+60%" claim (loop-discipline.md) misattributes**: the
  +60.89% in arXiv:2602.20426 is the full Trace-Free+ curriculum-learning
  framework's gain, not "description rewrites alone." Reword or drop
  "alone." The companion 9–12pp figure (2602.18914) is really 8.8–11.6pp —
  minor tightening.
- **Self-preference bias claim is too strong**: judge.md/rubric-format.md
  say it "largely vanishes" in pointwise decomposed reference-guided
  grading. Literature (arXiv:2506.02592, 2604.22891) shows it is
  *substantially reduced, not eliminated*. This is load-bearing — it
  justifies same-family (Claude-judging-Claude) mode. Keep the mode but
  reword to "reduced, not eliminated," and make the periodic cross-family
  spot-check audit a stated requirement of same-family mode rather than a
  suggestion.
- **BFCL citation overbroad**: order/extra-call tolerance is
  category-dependent in BFCL (separate parallel/multiple categories), not a
  benchmark-wide property — scope the citation.
- **Hooks have no native debounce**: PostToolUse + Edit/Write matcher is
  documented, but debouncing must be hand-rolled in the hook script;
  workflow.md/hooks-example.json should say the debounce lives in
  smoke.sh, not in Claude Code.
