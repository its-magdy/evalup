# Design Critique 3: Systematic Gap Enumeration (2026-07-18)

⚠ = ten most consequential. Condensed; organized by dimension.

## Lifecycle
- No dependency/venv story for scorer scripts; no `doctor` command; no version pinning of adopted OSS libs.
- No remediation workflow for uninstrumented apps (the most common first-run state).
- No headless/CI design despite CI being a stated goal.
- No staleness detection on refactor; no team-handoff spec (what lives in repo vs plugin-data vs local); no schema versioning/migration of adapter/baseline/dataset formats across plugin versions.

## Data
- ⚠ **Labeling UX entirely absent** — load-bearing step with no interface. Most likely step to simply not happen.
- Labels not versioned with rubrics (rubric v2 invalidates v1 labels; relabeling workflow unowned); single-SME assumption, no disagreement handling.
- ⚠ No stable case IDs / content hashes → paired stats break (pairing requires identical cases across runs); no rule for baselines when a case is edited.
- PII redaction has no mechanics (what detects it; Claude-based redaction itself exfiltrates; nested tool args; audit).
- Multilingual: generation-only; no per-language judge calibration or report slicing.

## Execution
- ⚠ Trace joining is a checklist line, not a design (correlation ID injection, wait/quiescence, partial-join policy).
- ⚠ No state isolation/reset between cases (case 12's writes contaminate case 13); session teardown unspecified.
- ⚠ No infra-flake vs model-failure taxonomy; no retry policy; failure counts noise-inflated.
- Streaming (when is response "done", TTFT capture), auth flows, run resumption, parallelism/rate limits, trace read path creds/lag, app health pre-flight — all unspecified.

## Reporting
- No report artifact spec (format, contents, audience split); QA/product without Claude Code cannot see results.
- No trend/time-series view; no failure→trace drill-down storage/linking; no flakiness ledger (regression alerts cry wolf); no slicing spec.

## Economics
- ⚠ No cost model (app spend + judge spend + Claude-reads-traces token blowup); no pre-run estimate/meter at 50/200/1000 cases.
- Optimize multiplier unbudgeted; hook has no debounce/cooldown; no judge-verdict caching keyed on (case, output, rubric-version); subscription-vs-API billing modes not carried into design.

## Security/compliance
- Secrets in committed adapter configs; no env-var indirection or schema rejection of literals.
- Judge sees raw user data BEFORE redaction (mining/reflection read traces through the API); no data-boundary statement or zero-retention guidance.
- ⚠ No live-tool safety gate: red-team/chaos/simulated users can trigger real side effects; nothing marks an adapter "safe to attack."
- No retention/deletion policy (user data in git history is permanent); no spend-authorization boundary for hooks/scheduled runs.

## Harness self-correctness
- ⚠ Discover has no validation loop (never cross-checked against observed traces; no confidence marking; no human sign-off). Mis-profile silently mis-scopes everything.
- ⚠ Normalizer loss undetectable → conservation checks needed (span counts in/out, orphaned parents, tool_call IDs without responses); lossy normalizer manufactures failures the optimizer then "fixes."
- ⚠ Garbage golden labels: expected OUTPUTS generated by same model family (generator collapse acknowledged only for inputs); multiple-valid-paths guard (BFCL end-state lesson) never adopted.
- Judge recalibration has no trigger/schedule/alert; matchers have no test corpus; run-health metadata (unjoined traces, judge API errors) not separated from failures.

## Comparability
- ⚠ **No run manifest**: must pin dataset version + case set, app git SHA, prompt snapshot, app model version (provider aliases silently upgrade!), judge model + judge-prompt version, rubric version, matcher/harness version, k, temperature. Every unpinned axis is a way two runs aren't comparable.
- No frozen comparable-core subset as the dataset grows (macro metrics drift with composition); cross-judge-version diffs not refused/flagged; branch-vs-main baseline semantics undefined.

## Multi-app/team
- No adapter workspace, no shared rubric/template library across apps, no locking/run registry for concurrent users, no roles (who may edit golden labels vs run evals).

## Other
- Eval-awareness mitigation has no mechanism; Tier-4 online evals undesigned (where judge runs, who pays); prompts-in-DB write path unaddressed; cost/latency layer has no assertion semantics; cumulative SME hours never totaled (classic stall cause); POSIX-only assumption; **no acceptance criteria for the plugin itself / no plugin self-eval suite**.
